## Why

The blog is English-only in structure today (one ad-hoc exception: a single Portuguese post manually paired with its English twin via prose cross-links and `hide_from_index`). The owner wants a real, sitewide Portuguese (pt-BR) presence: every page available in both languages, existing posts' titles translated (not their bodies, for now), a formal way to pair an English post with its Portuguese counterpart, a language switcher, and shared comment threads between paired language versions of the same post.

**Clarified scope**: "vcasadei.com.br/pt/" in the original request is `vcasadei.com/pt/` — a path prefix on the existing domain, not a second registered domain. `vcasadei.com.br` would be a genuinely separate domain requiring its own DNS/hosting setup, which the site's current single-`CNAME` GitHub Pages configuration doesn't support; that's explicitly out of scope.

## What Changes

- **No i18n plugin.** `jekyll-multiple-languages-plugin`/`jekyll-polyglot`/etc. aren't in the `github-pages` gem's whitelisted plugin set (the same constraint that ruled out a plain `theme:` gem — see `migrate-to-theme-gem`), so they wouldn't run in our Actions build. Instead, this uses a mechanism the theme *already has*: every page/post can set `lang:` in its front matter, and the theme's own `get-lang.html`/`get-locale-string.html` snippets already prefer `page.lang` over `site.lang` for all UI strings (nav labels, "Read more", date formats, etc.), falling back to English automatically when a string isn't translated. No new dependency required.
- **Portuguese pages** at `/pt/` (home), `/pt/archive.html`, `/pt/about.html` — new page files with `lang: pt-BR` and explicit `permalink:`s, reusing the existing layouts.
- **Portuguese posts** live under a new `_posts/pt/` folder; a `defaults:` scope rule in `_config.yml` automatically applies `lang: pt-BR` and a `/pt/:year/:month/:day/:title.html` permalink to anything placed there — no plugin, just core Jekyll config. The existing ad-hoc Portuguese HackTown post moves into this structure (its URL changes from `/2026/09/11/assistente-...` to `/pt/2026/09/11/assistente-...`; flagged since it's a real URL change, though the post is new enough that this is low-impact).
- **Post pairing and fallback**: a new `translation_key` front-matter field, set to the same value on an English post and its Portuguese counterpart when (and only when) both exist. The Portuguese archive/home listings show a translated title (see below) for *every* post; for posts with no `translation_key`/no file under `_posts/pt/`, the listing links straight through to the existing English post — that's the "fallback to English" behavior, implemented as "there's simply no separate Portuguese URL to visit," not a redirect.
- **Translated titles for existing posts**: adds a `title_pt` front-matter field to the 5 English-only posts (drafted now for owner review, same treatment as the `finish-about-page` change gave `about.md` — a draft to edit, not final copy) so the Portuguese listings can show real titles without needing full translated bodies.
- **Language-filtered listings**: `_includes/article-list.html`, `tags.html`, `paginator.html`, and `search-data.js` (currently filter only on the `hide_from_index` boolean from the earlier PT-post-hiding change) are generalized to filter `site.posts`/`site.pages` by matching each post's `lang` (defaulting to `en`) against the *current listing page's own* `lang` — so the English archive shows only English-flagged content and `/pt/archive.html` shows only Portuguese-flagged content. This supersedes the narrower `hide_from_index` mechanism for this purpose.
- **Language switcher**: a small UI element (reintroducing a local override of `_includes/header.html`, currently absent as an unmodified duplicate of the theme's own after `migrate-to-theme-gem`) that links to the current page's paired counterpart when one exists, or to `/pt/`/`/` generally otherwise. The same override also makes the existing "Archive"/"About" nav links language-aware, since `_data/navigation.yml`'s schema has no native per-language URL (only per-language *labels*).
- **Shared comments across paired posts**: giscus's mapping strategy changes sitewide from `pathname` to `specific`, with `data-term` set to `page.translation_key` when present, else `page.key`. This means an English/Portuguese pair shares one discussion thread; unpaired posts keep their own unique thread via their existing `key`. **Breaking change**: any comments posted under the current `pathname`-mapped discussions (the comment system is only a few days old) would no longer be reachable from the old mapping — acceptable given how new and low-traffic the feature is, but called out explicitly.
- **Known limitation, not fixed here**: GitHub Pages only serves one root `/404.html` for any unmatched path, including under `/pt/` — a fully localized 404 page isn't achievable without extra infrastructure. Out of scope.

## Capabilities

### New Capabilities
- `site-internationalization`: The site's bilingual (English/Portuguese) structure — per-page language declaration, language-filtered listings, post pairing with English fallback, the language switcher, and shared comments across paired posts.

### Modified Capabilities
(none — `hide_from_index` was implemented ad hoc in an earlier change and never captured as its own formal spec; this change's `site-internationalization` capability supersedes that behavior going forward rather than modifying a pre-existing requirement)

## Impact

- **Affected files**: `_config.yml` (new `defaults:` scope for `_posts/pt/`, giscus mapping change), new `pt/index.html`, `pt/archive.html`, `pt/about.md`, new `_posts/pt/` directory (existing PT post moved here), `_data/locale.yml` (add a `pt-BR` block), `_data/navigation.yml` (no schema change needed if the header override handles URL switching directly), new local override `_includes/header.html`, `_includes/article-list.html`/`tags.html`/`paginator.html`/`search-data.js` (lang-based filtering), `_includes/comments-providers/custom.html` (giscus mapping), every existing post (new `title_pt` field).
- **Affected systems**: none beyond the Jekyll build itself — no new plugins, no new external services.
- **User-facing**: a real `/pt/` section appears; the language switcher appears on every page; giscus comment threads for the existing HackTown post pair merge into one thread (previously two separate, both very new/likely empty).
- **Depends on**: `finish-about-page` (still open) for real English About content to translate — not a hard blocker; the Portuguese About page can ship with a placeholder/draft translation and be refined once the English source is final.
- **Content work required from the owner**: review/edit the drafted `title_pt` values and the Portuguese About page draft — this proposal does not invent final copy on your behalf.
